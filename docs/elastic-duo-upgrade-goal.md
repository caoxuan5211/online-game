  ## P0 必做：单人模式

  单人模式不需要创建房间，也不需要等待其他玩家。

  流程：

  开始游戏
    -> 游戏选择
      -> Elastic Duo
        -> 单人模式
          -> 进入单人准备 / 直接开始

  单人玩法规则：

  - 只有一个小球。
  - 地图上随机生成一个圆形目标区域。
  - 玩家需要在规定时间内进入目标区域。
  - 玩家进入目标区域后，刷新下一个随机目标区域。
  - 每完成一次目标，得分 +1 或进入下一轮。
  - 难度越高：
      - 目标区域停留时间越短
      - 障碍更多
      - 目标区域可能更小
      - 小球速度 / 障碍速度可提高

  - 撞到障碍则失败。
  - 单人模式也要支持重开、返回大厅 / 返回模式选择。

  单人模式 UI：

  - 顶部显示时间、分数、难度。
  - 右上角显示目标区域倒计时。
  - 目标区域要有明显颜色、边缘发光和轻微脉冲动画。
  - 目标区域出现前可以有短暂提示，不要突然刷在玩家身上或障碍内部。
  - 失败复盘显示：
      - 分数
      - 存活时间
      - 难度
      - 失败原因
      - 重开
      - 返回模式选择

  随机目标区域规则：

  - 不要生成在障碍物上。
  - 不要生成在屏幕边缘不可达区域。
  - 尽量离玩家当前位置有一定距离，但不能离得过远。
  - 如果随机点无效，重新采样，最多尝试若干次后使用兜底位置。

  ## P0 必做：多人几何连接机制

  当前 2 人是一条线。扩展多人时，玩家之间形成多边形。

  规则建议：

  1 人：无连接，目标区域模式
  2 人：一条线
  3 人：三角形
  4 人：四边形

  多人连接显示：

  - 2 人：连接线 A-B
  - 3 人：连接线 A-B、B-C、C-A，形成三角形
  - 4 人：连接线 A-B、B-C、C-D、D-A，形成四边形
  - 可选：显示半透明填充面，表达团队区域
  - 可选：显示边长压力，边太长时变红，边太短时变亮或压缩

  多人玩法核心：

  - 玩家整体保持队形，避开障碍。
  - 任意玩家撞障碍失败。
  - 任意连接边碰到障碍可选：
      - 方案 A：连接边碰障碍也失败，更硬核
      - 方案 B：只有小球碰撞失败，更易上手
      - 推荐先实现 B，后续难度高时启用 A

  - 多人目标区域可以是：
      - 方案 A：所有玩家都需要进入各自颜色区域
      - 方案 B：多边形整体中心点进入目标区域
      - 方案 C：多边形覆盖目标区域
      - 推荐先实现 B，逻辑简单、反馈清楚

  多人状态计算：

  - 根据玩家数量动态生成连接边。
  - 不要写死两个玩家。
  - 使用玩家数组排序生成连接关系。
  - 2/3/4 人都应共用同一套连接生成逻辑。

  示例逻辑：

  function getEdges(players) {
    if (players.length <= 1) return []
    if (players.length === 2) return [[players[0], players[1]]]
    return players.map((player, index) => [
      player,
      players[(index + 1) % players.length]
    ])
  }

  ## P0 必做：小球尺寸和碰撞容错

  当前小球偏大，障碍密集时太难。

  请调整：

  - 小球视觉尺寸缩小约 15%-30%。
  - 碰撞半径也同步缩小，但不要小到视觉和碰撞不一致。
  - 连接线宽度适当变细。
  - 障碍碰撞判定可以略微宽松。
  - 难度 1-3 应明显更适合新手。
  - 难度 5 保持挑战，但不要开局几秒必死。
  - 移动端小球可以比桌面略大一点点，保证可见性。

  建议参数方向：

  - playerRadius 从当前值下调到 0.7x - 0.85x
  - collisionRadius 与视觉半径保持一致或略小
  - lineWidth 下调 10%-25%
  - obstacleSpawnSafeDistance 增大，避免出生点附近立即失败

  不要只缩 CSS，必须确认实际碰撞半径也合理。
